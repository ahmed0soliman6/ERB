نطاق الوثيقة: التصميم فقط. لا تتضمن هذه الوثيقة كودًا أو ملفات مشروع.1. القرار التنفيذيالنظام المقترح هو تطبيق Desktop محلي يعمل على جهاز كمبيوتر واحد، ويستخدم SQLite كقاعدة البيانات الوحيدة. لا يعتمد تشغيله على الإنترنت أو على خادم خارجي أو على Firebase أو Supabase أو أي قاعدة بيانات سحابية.التقنية الأساسية المقترحة هي C# مع .NET Framework 4.8 وWindows Forms، مع نشر نسخة x86 مدمجة بالمكونات اللازمة. اختيار Windows Forms مقصود لتقليل استهلاك الموارد، وتجنب Browser/WebView، ودعم الأجهزة الضعيفة، وتوفير سلوك مستقر مع Windows 7 وWindows 8.1 وWindows 10 وWindows 11. توضح وثائق Microsoft أن .NET Framework 4.8 قابل للتثبيت على Windows 7 SP1 بنسختيه 32-bit و64-bit، وعلى Windows 8.1 وWindows 10، بينما تعرض SQLite رسميًا ملفات Windows x86 وx64 [1] [2].شرط توافق مهم: المقصود بـ Windows 7 هو Windows 7 SP1، والمقصود بـ Windows 8 في مصفوفة القبول هو Windows 8.1. أما Windows 8.0 الأصلي فليس مكافئًا لـ Windows 8.1 من ناحية دعم .NET Framework، ولذلك يجب اعتباره اختبار قبول منفصلًا قبل الالتزام به تجاريًا. إذا كان دعم Windows 8.0 إلزاميًا، فلا يبدأ التنفيذ قبل بناء نموذج توافق واختباره على جهاز حقيقي.سيتم بناء النظام حول قاعدة صارمة:Stock Movements = Single Source of Truthأي أن الرصيد لا يكون قيمة تشغيلية مستقلة قابلة للتعديل اليدوي. الرصيد يحسب من الحركات المعتمدة، بينما يمكن استخدام لقطات مؤقتة للأداء أو للتقارير بشرط أن تكون قابلة لإعادة البناء والتحقق.2. حدود النظاميدير النظام المخزن الرئيسي، ومخزن الطوارئ، ومخزن أدوية العمليات، ومخزن مستلزمات العمليات، وأي مخازن مستقبلية يضيفها المسؤول من الشاشة دون تعديل البرنامج.يدعم النظام قائمة أصناف موحدة. الصنف الواحد يمكن أن يظهر في عدة مخازن، لكن لا ينشأ له سجل صنف جديد لكل مخزن. يدعم النظام التوريد، والتحويل، والصرف، والاستهلاك، والجرد، وتسويات الجرد، وبطاقة حركة الصنف، والتقارير، والمستخدمين والصلاحيات، وسجل التدقيق، واستيراد Excel، وتصدير Excel وPDF، والنسخ الاحتياطي والاستعادة، والترخيص المحلي الموقّع.# ERB
